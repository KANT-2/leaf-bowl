# 이미지 업로드와 파일 정리

이미지는 PostgreSQL에 URL을 저장하고 `ADMIN_DATA_DIR/images`에 파일을 둔다. 배포 릴리스 밖의 고정된 절대 경로를 사용하고 DB와 이미지 디렉터리를 함께 백업한다. 폴더 쓰기 권한은 앱 실행 계정에만 부여한다. 운영 환경의 경로·권한·백업 상태는 코드 검사만으로 확인되지 않는다.

## 업로드와 공개 조회

관리자 업로드는 서버 관리자 세션과 같은 출처를 확인한다. 요청 본문은 6MiB, 파일은 5MiB, 전체 관리자 업로드는 프로세스당 분당 30회로 제한한다. 리뷰 사진은 장당 1MiB, 최대 3장이다. 구매 권한 보완은 [PR #138](https://github.com/KANT-2/leaf-bowl/pull/138)에서 진행한다.

확장자·Content-Type·시그니처만으로 통과시키지 않는다. Sharp로 PNG/JPEG/WebP 정지 이미지를 완전히 디코딩하고 다시 인코딩한다. 최대 1600만 픽셀, 프로세스당 동시 디코딩 2개, 처리 시간 5초와 결과 파일 용량 한도를 적용한다. EXIF 등 메타데이터와 뒤에 덧붙인 바이트는 제거한다. 입력 스트림과 브라우저 요청은 30초로 제한한다.

서버가 생성한 UUID 파일명으로 임시 파일을 쓴 뒤 원자적으로 이름을 바꾼다. 파일 쓰기·이름 변경 실패나 리뷰 DB 저장 실패 시 임시/미참조 파일을 정리한다. 응답에 내부 경로나 오류 내용을 포함하지 않는다.

`GET /api/admin/images/[key]`는 고객에게 노출되는 상품·재료·리뷰·배너·시즌 이미지에만 익명 조회를 허용한다. 저장 전·숨김·휴지통·관리자 전용 이벤트 이미지는 관리자 세션으로 미리 본다. 응답은 `private, no-store`, `nosniff`로 보내고 조회마다 현재 공개 참조를 확인한다. 기존에 받은 이미지 사본까지 회수할 수는 없다. 릴리스의 `public/admin-assets/uploads`는 과거 호환용 정적 파일이므로 별도 공개 경로가 남아 있으며 이 정리 작업으로 삭제하거나 비공개로 바꾸지 않는다.

## 파일 수명주기

- 교체·제거·영구 삭제 후에는 카탈로그와 이벤트의 전체 참조를 다시 확인해 마지막 참조가 사라진 파일을 정리한다.
- 공유 이미지, 숨긴 항목, 휴지통 항목, 종료된 이벤트는 편집·복원할 수 있으므로 파일을 보존한다. 배너의 PC·모바일·이전 호환 필드도 포함한다.
- 취소·편집 미저장·요청 중단 파일과 부분 임시 파일은 24시간 동안 보존한다. 이후 참조가 없는 파일만 정리한다.
- 업로드·카탈로그/이벤트 저장이 정리를 유발한다. 오래된 파일 정리는 프로세스당 최소 5분 간격이며 한 번에 최대 2000개를 처리한다. 별도 타이머나 카탈로그 폴링을 추가하지 않는다.
- 파일 정리와 새 참조 저장은 같은 카탈로그 DB 잠금을 사용한다. 이미 정리된 URL을 새로 붙이면 400으로 거절하고 재업로드를 안내한다.
- 저장 후 정리 실패는 이미 완료한 DB 변경을 실패로 되돌리지 않는다. 서버 로그의 `[images] maintenance failed`를 확인한 뒤 수동 정리를 다시 실행한다.

## 수동 점검·정리

환경변수 또는 `.env.local`에 같은 `DATABASE_URL`, `ADMIN_DATA_DIR`를 설정한다. 해당 DB의 최신 마이그레이션을 먼저 적용한다.

```sh
# 삭제하지 않고 오래된 미참조 파일 개수 확인
npm run images:prune

# 확인한 환경에서 실제 정리
npm run images:prune -- --apply
```

출력은 후보 개수와 실제 적용 여부다. 2000개 한도에 도달하면 다시 실행할 수 있다. 서로 다른 DB가 같은 파일 디렉터리를 공유하면 참조 확인이 불완전해지므로 환경별 디렉터리를 분리한다. 여러 앱 인스턴스가 같은 DB를 사용할 때는 같은 영속 파일 저장소를 사용해야 한다. 요청/디코딩 제한은 인스턴스별이며 전체 디스크 용량 할당·외부 공유 rate limit은 인프라에서 관리한다.

## 브라우저 동작

업로드 중 저장과 상품 편집창의 X/Escape 닫기를 막는다. `업로드 취소`는 요청을 중단하고 다시 선택할 수 있게 한다. 화면 이동·편집 페이지 교체로 컴포넌트가 사라지면 요청을 중단하고 늦은 결과를 화면 상태에 적용하지 않는다. 여러 PC/모바일/시즌 업로드가 겹쳐도 마지막 요청이 끝날 때까지 저장을 막는다.
