# 업로드 조치 및 보안 감사

2026-10-12 기준으로 `main`의 배너·이벤트·복수 드레싱 변경을 포함해 서버 API, 인증·권한, 공개 데이터, 업로드, 결제, 브라우저 이동, 저장소 비밀정보와 npm 의존성을 검사했다. 작업은 상위 [#134](https://github.com/KANT-2/leaf-bowl/issues/134)에서 추적한다. 아래 수정 사항의 운영 반영에는 각 PR의 리뷰·CI·병합·배포가 필요하다.

## 기존 방어 확인

- 관리자 API는 DB에서 유효한 관리자 세션을 확인하며 쿠키 존재만으로 통과하지 않는다. 미들웨어의 쿠키 검사는 진입 편의를 위한 것이며 서버 페이지·API에서 다시 권한을 확인한다. DB 인증 조회 장애는 허용으로 전환하지 않고 503으로 처리한다. 새 이벤트 GET/PUT도 무인증·비회원·위조 쿠키와 외부 출처 요청을 거절하는 회귀를 추가했다.
- 관리자/주문/결제 쓰기 API는 출처를 검사한다. 비브라우저 요청처럼 Origin이 없는 경우에도 세션 권한 확인이 필요하다. 프록시의 실제 HTTPS 주소는 `APP_ORIGIN`으로 지정하며 임의의 `X-Forwarded-*` 헤더를 인증 근거로 쓰지 않는다.
- 세션 토큰은 HttpOnly·SameSite=Lax이며 production에서는 Secure다. DB에는 토큰 해시를 저장하고 관리자 비밀번호는 scrypt로 해시한다. 만료·로그아웃·권한 구분 회귀가 있다.
- 주문 조회와 토스 확인은 비회원 세션 소유권을 확인한다. 가격·배송비는 서버 카탈로그를 기준으로 계산하고 주문 시점의 금액·이름을 보존한다. 토스 테스트 확인에서는 금액·orderId·paymentKey·통화·성공 상태를 확인한다. 중복 확인, 외부 응답 유실, DB 롤백 후 복구, 상품 삭제 후 금액 보존 회귀를 PostgreSQL에서 실행했다. 실제 결제 운영 키·정산은 감사 범위에 포함하지 않았다.
- 공개 카탈로그는 관리자 세션·주문 연락처·구매별 리뷰 소유권 테이블을 포함하지 않는다. 숨긴 상품의 내용과 삭제 리뷰를 공개 응답에서 제거한다. 개인정보가 있는 API 응답은 no-store다.
- 업무/화면 코드에서 `dangerouslySetInnerHTML`, `eval`, 사용자 입력을 실행하는 child_process, 문자열 SQL 실행을 찾지 못했다. 운영 SQL은 Prisma와 매개변수화된 쿼리를 사용한다. 이 결과는 코드 검색·검토 결과이며 모든 공격 가능성이 없다는 증명은 아니다.
- Git 추적 파일 중 환경 파일은 `.env.example`이며 런타임 `.env.local`, `.data`, `.deploy`, 업로드·릴리스 데이터는 제외한다. 실제 운영 비밀값을 출력하거나 운영 파일을 삭제하지 않았다. Git 전체 과거 이력이나 외부 서비스의 자격증명 상태는 확인하지 않았다.

## 의존성 감사

`npm audit --json`은 High 5개, `npm audit --omit=dev --json`은 0개를 보고했다. 5개는 같은 개발 도구 의존성 사슬에서 전파된 한 가지 advisory다.

```text
eslint-config-next 16.4.0
→ @next/eslint-plugin-next 16.4.0
→ fast-glob 3.3.1
→ micromatch 4.0.8
→ braces 3.0.3
```

[GHSA-vfj7-8cjw-p6xm / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)은 깊게 중첩된 brace 패턴으로 호출 스택을 소진하는 문제이며, 확인 당시 수정된 버전이 없다. 현재 사슬은 ESLint의 저장소 파일 탐색에 쓰이고 외부 HTTP 요청 입력을 이 API에 전달하는 경로를 찾지 못했다. 이는 이 저장소의 코드·lockfile을 검토한 판단이다. 운영 의존성 결과 0개는 개발 단계 취약점을 해결했다는 뜻이 아니다.

`npm audit fix --force`가 제안하는 eslint-config-next 14.x 다운그레이드는 Next 16.4 도구 계약을 깨므로 적용하지 않았다. 공개 린트 서비스에 외부 glob 입력을 받지 않고, 비신뢰 저장소 변경을 운영 비밀이 있는 환경에서 실행하지 않는다. 수정 버전 또는 호환 가능한 의존성 사슬이 나오면 lockfile 갱신 후 CI 전체를 재검증한다. 잔여 항목은 [#147](https://github.com/KANT-2/leaf-bowl/issues/147)에서 추적한다.

## 검증 범위와 남은 운영 확인

단위/API 회귀, 모듈 경계, 실제 PostgreSQL 18 트랜잭션·파일 정리 검증, 업로드 UI 브라우저 확인과 CI의 기본 Next.js 빌드·빌드 후 타입 검사를 기준으로 한다. 이 작업 환경의 기본 Turbopack 빌드는 CSS 로더가 여는 내부 포트의 권한 제한으로 실패하므로 로컬 빌드 성공으로 기록하지 않는다. 업로드 브라우저 확인은 격리 테스트 DB와 Webpack 개발 서버를 사용했다. PR별 최종 성공 SHA·CI 링크·실제 검증 결과는 각 PR 본문에 기록한다.

운영 프로세스의 실제 `ADMIN_DATA_DIR`, 계정 권한, DB/파일 백업 및 복원, 디스크 할당, TLS 프록시 설정과 배포 후 확인은 별도 운영 확인이 필요하다. 속도·디코딩 제한은 프로세스별이므로 여러 인스턴스 전체 제한에는 공유 저장소/프록시 설정이 필요하다. 모든 인스턴스는 같은 DB에 대응하는 영속 이미지 디렉터리를 사용하고 서로 다른 환경의 DB는 이미지 디렉터리를 공유하지 않는다.

비회원 주문 세션은 30일이 지나거나 쿠키가 없어지면 기존 구매의 리뷰 권한을 찾을 수 없다. 브라우저 체험용 이메일 로그인과 프로필은 실제 고객 계정이 아니며 기기 간 주문 소유권 증명이 되지 않는다. 실제 고객 인증 연결은 별도 기능이다. 과거 공개 정적 업로드 파일은 릴리스 자산으로 남아 있으며 런타임 파일 정리 정책으로 비공개 전환되지 않는다. CSP는 인라인 코드 및 토스/주소 검색 연동을 함께 설계해야 하므로 이번 공통 헤더 적용에 포함하지 않았다.
