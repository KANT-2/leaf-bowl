# 관리자 기능 통합 계획 및 확인 방법

목적: 기존 고객 사이트를 유지하면서 지금까지 구현한 관리자 기능을 /admin에 통합한다.
범위: 메뉴/옵션/재료/시즌/리뷰/위치 관리, 관리자 고객 미리보기, 이미지 업로드, 현재 데이터 이관.
수용 기준: 고객 경로 유지, 모든 관리자 메뉴 작동, 수정 데이터와 이미지 재시작 후 유지, 타입/빌드/린트 통과.
데이터 연동 작업: #22 (`feat/22-shared-catalog`).

## 실행
`npm ci`, `npm run dev` 후 `/`에서 기존 고객 사이트, `/admin`에서 관리자 사이트를 확인한다.
관리자 고객 미리보기의 iframe과 새 창 링크는 실제 고객 홈(`/`)을 표시한다.
`/admin/preview`는 관리자 권한을 확인한 뒤 같은 고객 앱(`/`)으로 이동한다. 별도 템플릿·스크립트는 유지하지 않는다.
고객 홈·메뉴·상품 상세·옵션·장바구니·재료·리뷰는 관리자와 동일한 카탈로그를 읽는다.
관리자 저장은 같은 브라우저의 탭/iframe에 BroadcastChannel로 즉시 알리고, 다른 접속자는 3초 간격 조회 및 창 복귀 시 최신 revision을 반영한다. 저장 전 편집 내용은 고객에게 반영하지 않는다.
고객 리뷰도 서버 카탈로그에 저장하며 관리자에서 삭제하면 고객 화면에서 제거된다. 장바구니는 브라우저에 보존하지만 상품·옵션 가격과 판매 가능 여부는 최신 카탈로그로 계산한다.
관리자 경로/API는 DB 관리자 세션으로 보호하며 계정 준비는 [PostgreSQL 가이드](postgres.md)를 따른다.

## 저장소
현재 카탈로그·리뷰와 운영 설정은 PostgreSQL에 저장한다. `db/seed.sql`로 초기화하며 이전 JSON은 `npm run db:import`로 명시적으로 이관한다. 일반 조회·저장은 정적 시드로 필드를 복원하지 않는다.
숫자 상품 ID는 최초 할당 후 유지하여 상품 URL과 장바구니가 다른 상품으로 연결되지 않도록 한다.
업로드 이미지는 ADMIN_DATA_DIR 환경변수 경로(기본 .data/admin)에 저장된다. 릴리스 디렉터리가 교체되는 배포에서는 고정 절대 경로를 사용한다.
이미지 POST 5MB 제한, 파일 시그니처 검사, catalog revision을 통한 동시 저장 충돌 방지를 유지한다.
삭제 리뷰/품절/숨김 등 기존 저장 상태를 보존한다.

## 기존 관리자 통합 검증 결과 (데이터 연동 전)
- npm ci, npm run lint(오류 0개, 경고 17개), npm run build, npx tsc --noEmit 통과.
- /, /product/0, /product/0/reviews, /admin, /admin/preview, /api/admin/catalog HTTP 200 확인.
- 현재 관리자 메뉴 21개, 재료 18개, 리뷰 5개와 숨김/삭제 상태 유지 확인.
- 저장 후 재조회, 오래된 revision 저장 409, 다른 Origin 저장 403, PNG 업로드/재조회 확인.
- 고객/관리자 루트 레이아웃 분리로 기존 고객 화면 구조 유지.
- 브라우저의 localhost:5174 접근 권한이 거절되어 시각 스크린샷 검증은 수행하지 못했다.

## 데이터 연동 확인 방법 (#22)
1. `/menu`와 `/admin`을 각각 열고 관리자에서 이름·가격·이미지를 저장한다. 고객 페이지가 새로고침 없이 갱신되는지 확인한다.
2. 상품을 숨김/삭제하면 목록에서 제거되고 품절이면 담기·주문을 막는지 확인한다.
3. 상품 상세에서 연결된 옵션 그룹의 필수/다중 선택을 확인하고 옵션 가격 변경 후 장바구니 합계를 확인한다.
4. 메인 문구, 시즌 노출·순서, 재료·리뷰·위치 수정이 고객 화면에 반영되는지 확인한다.
5. `node tests/catalog.test.cjs`로 임시 폴더에서 초기화·저장·충돌·이관·삭제 반영을 검증한다.

배달 운영 설정은 기존 관리자 화면에서 보류 상태이므로 고정 정책을 유지한다. 브라우저에만 저장된 과거 고객 리뷰도 고객 화면 접속 시 서버로 이관한다. 동일 ID의 재등록은 중복을 만들지 않으며 관리자에서 삭제된 동일 ID 리뷰는 복원하지 않는다.

## 데이터 연동 검증 결과
- lint 오류 0개, 기존 경고 10개 및 TypeScript 검사 통과.
- `node tests/catalog.test.cjs`: 초기값 일치, 저장/재조회, ID 유지, revision 충돌, 백업/이관, 옵션/장바구니, 리뷰 삭제, 공개 데이터 필터링 등 테스트 4개 통과.
- 고객 홈, 메뉴, 상품 상세, 상품 리뷰, bowl match, 관리자 페이지 HTTP 200 확인.
- 실제 개발 서버의 Chromium 화면에서 API 응답만 모의로 변경하여 저장 알림·주기 조회로 상품명/가격/숨김/재료가 갱신되는지 확인. 장바구니 옵션 가격 자동 재계산과 고객 홈 미리보기 확인, 페이지 오류 없음.
- 브라우저 재현: `npx --yes --package playwright -c 'node tests/catalog-browser.cjs'` (`FRONT5_BASE_URL`로 서버 주소 지정 가능). 실행 환경에 Chromium 및 해당 런타임 라이브러리 필요.
- 운영 빌드는 Turbopack CSS 처리 중 환경의 포트 바인딩 권한 오류(`Operation not permitted`)로 완료하지 못했다. CI에서 운영 빌드를 확인해야 한다.
- 화면 증빙: `docs/screenshots/shared-catalog/` (브라우저 테스트의 모의 응답을 표시한 화면).
