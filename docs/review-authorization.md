# 리뷰 작성 권한

리뷰 작성은 브라우저의 체험 로그인 이메일이 아니라 서버가 발급한 `lb_guest` HttpOnly 쿠키와 해당 주문의 `customer_session_id`를 기준으로 한다. 유효한 세션이 소유한 `completed` 주문의 샐러드 품목만 등록할 수 있다. 체험 프로필은 화면 표시 용도이며 서버 고객 계정은 아니다.

`POST /api/reviews`는 `orderItemId`를 필수로 받는다. 세션이 없거나 만료되면 401, 없는/다른 세션의 품목이면 404, 미완료 주문이나 메뉴 불일치이면 400, 이미 작성한 구매나 다른 구매에 사용된 리뷰 ID이면 409를 반환한다. 세션별 분당 10회, 프로세스 전체 분당 60회로 제한한다. 이미지 저장 전에 검사하고 카탈로그 저장 트랜잭션 안에서 다시 검사한다.

`review_submissions`는 주문 품목당 하나의 제출 ID와 소유 세션을 보관한다. 이 이력은 리뷰 영구 삭제와 세션 만료 후에도 유지하여 재등록을 막는다. 동일 세션·품목·리뷰 ID의 재시도는 기존 결과로 처리한다. 카탈로그 배타 잠금과 DB 유일 제약으로 동시 등록을 막는다. 이력에는 리뷰/세션 FK가 없으므로 별도 개인정보 보존 정책을 정하면 주문 보존 기간과 함께 정리 정책을 설계해야 한다.

`GET /api/reviews`는 로그인된 주문 세션의 `{ submissions: [{ reviewId, orderItemId }] }`만 반환하며 `no-store`를 사용한다. 공개 카탈로그에는 소유 세션과 주문 품목을 넣지 않는다. 작성 가능 목록과 내 리뷰는 서버 제출 이력을 사용하므로 브라우저 저장소 삭제 후에도 구매 중복을 막는다.

기존 리뷰에는 신뢰할 수 있는 주문 연결이 없어 자동으로 구매 이력을 역으로 만들지 않는다. 주문 품목 없는 브라우저 캐시도 서버로 자동 제출하지 않는다. 세션 쿠키 삭제·만료 후 과거 주문 소유권을 복구하는 기능은 현재 없다. 다른 기기에서도 주문을 공유하려면 실제 고객 인증과 계정-주문 연결이 별도로 필요하다.

검증: API 회귀는 `npm test`, 실제 PostgreSQL의 동시 등록·다른 세션·상품 불일치·영구 삭제 후 재시도는 전용 테스트 DB에서 `npm run test:db`로 실행한다. `0008_review_purchase_claims` 마이그레이션을 코드 배포 전에 적용한다.
